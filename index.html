How it works

  1. 01

    Write a card

    Each card is a markdown file with a question above the rule and an answer below it. Put them wherever makes sense — /cards, next to your notes, inside an existing repo.

  2. 02

    Commit it

    Cards live in git like everything else you write. Edit history, blame, and diffs work exactly the way you'd expect — no separate sync layer to trust.

  3. 03

    Review in your terminal

    recall review pulls due cards using SM-2 scheduling and runs the session right in your shell, no browser tab required.

Catalog

FORMAT

Plain markdown storage

No proprietary database, no export step. A card is a text file — readable in any editor, diffable in any git host.

SCHEDULE

SM-2 spaced repetition

The same scheduling algorithm behind most modern spaced-repetition tools, tuned for short terminal sessions instead of long browser ones.

SYNC

Git-native

Push and pull your deck like any other repo. Study on a laptop, sync on a desktop, resolve conflicts the way you already know how.

PRIVACY

Runs entirely local

No server, no account, no telemetry. Your cards and your review history never leave the repo you put them in.
